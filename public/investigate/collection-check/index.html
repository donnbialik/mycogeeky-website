Collection Check

Review public iNaturalist fungi records for missing or conflicting specimen and sequencing information.

iNaturalist checking… New here?
  1. 1Whose records: an iNaturalist username, and optionally a date
  2. 2Check the fields: confirm which observation fields mean voucher, plate, sequence or GenBank
  3. 3See the gaps: each check lists the records it caught, with links
  4. 4Review specimens: compare regional records and download the review list
  5. 5Write it back (optional): add the keep reason to your own observations

1Whose records?

Reads fungi observations (including lichens) one page of 200 at a time, about one request a second as iNaturalist asks. Nothing is written to iNaturalist unless you use step 5.

2Fields found

Observation fields are named freely, so they’re recognised by name. Untick any that don’t mean what the label says, or add one the tool missed.

3What’s missing a step

These flags reflect the public records and fields this check reads. Open a flag, then select an observation number. On the iNaturalist website, use Observation Fields to review or update metadata on records you can edit. Rerun Check records after saving. iNaturalist’s guide to Observation Fields

4Review specimens by regional documentation

Compare other people’s verifiable iNaturalist records and see how many have a DNA Barcode ITS field. The primary region sets the review priority. The second region adds local context. How the counts work

How “rarely documented” is worked out, and its limits

Counts exclude the account you scanned. The percentage option uses the selected region’s species-count distribution, includes ties at the cutoff, and shows the resulting record threshold. Zero means the query returned no matching records.

Observations reflect uneven sampling and identifications can change. The counts measure documentation on iNaturalist. Estimating abundance or conservation status requires other evidence. The ITS column counts records with the DNA Barcode ITS field. It can miss results stored elsewhere and does not check sequence quality. Scientific guidance on using iNaturalist data

5Write the keep reason to iNaturalist (optional)

Adds the suggestion from step 4 to each observation as an observation field, so the reason a specimen was kept travels with its record. Only your own observations, and nothing is written until you preview and confirm.

a. Choose the field

Recommended: a text field you create once on iNaturalist (Observation fields → New), named for example Voucher keep reason (MycoView), with allowed values provisional|rarely documented|rarely sequenced|well documented.

b. Connect to iNaturalist

Sign in to iNaturalist and open inaturalist.org/users/api_token. Copy the api_token value and paste it here. It stays in this page’s memory, is sent only to iNaturalist, and is gone when you close the page. Tokens last about 24 hours.

c. Preview, then write

The log stays on this page. Download a copy before leaving if you need to reconcile the batch later.
